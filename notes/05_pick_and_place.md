# 具身智能 Pick & Place：从真实接触到完整抓放

统合日期：2026-10-25。本文整合 Day11–13 的抓取、规则状态机和环境判定，并连接 Day15 四维专家及 BC。项目对象是仿真中的 Panda、平行夹爪、单 Cube 与水平台面。

运动学推导见 [FK/IK](02_robot_kinematics.md)，环境接口见 [仿真环境](01_simulation_environment.md)，学习训练见 [BC](03_imitation_learning_bc.md) 和 [PPO](04_reinforcement_learning_ppo.md)。

## 1. 抓放任务到底要求什么

完整任务不是 TCP 去两个坐标点，而是：

```text
接近物体 → 形成夹持 → 稳定抬离支撑 → 搬运
         → 在目标处建立支撑 → 松爪 → 撤离 → 物体仍稳定留在目标
```

每一段的控制对象与证据不同。臂运动控制 TCP，任务目标通常描述 Cube 中心；夹爪命令只表示意图，接触与物体状态才提供抓持证据。

当前任务中 Cube 只在 reset 初始化时设置状态，执行阶段不写 Cube qpos、不用 weld 或 mocap 把物体粘在手上，也不靠自动重抓隐藏失败。

| 对象/量 | 当前定义 |

| Cube | 边长 0.05 m，质量 0.10 kg，自由刚体 |
| 台面顶面 | z=0.20 m |
| 静放 Cube 中心 | z=0.225 m |
| TCP | Hand 局部 [0,0,0.10] m，方向同 Hand |
| 目标含义 | 放置后的 Cube 中心，不是 TCP，也不是桌面高度 |
| 夹爪名义总开度 | 两个滑动关节位移之和，名义范围 0–0.08 m |

## 4. 夹爪开度如何变成动作

两个手指通过一个固定腱分配驱动：

\[
w=q_{f1}+q_{f2},\qquad
l_{\text{tendon}}=0.5q_{f1}+0.5q_{f2}=w/2.
\]

仿射伺服静态表达为：

\[
F=g\,u+b_0+b_1\,gear\,l.
\]

按目标开度反解：

\[
u=-b_0/g-\frac{b_1\,gear}{2g}w.
\]

控制器从实际模型参数推导映射，再对 width/ctrl 分别限幅，不硬套别的夹爪系数。关节位移之和是名义开度，不是指垫接触面间距的精确标定。

动作 -1/0/+1 对应名义开度 0/0.04/0.08 m。实际开度、执行器力和左右接触法向力是不同量；闭合命令不能代替反馈，接触物体后实际开度也不必归零。

## 5. 接触检测：从“碰到”到“候选夹持”

`PandaContactDetector` 读取已经求解的接触，要求约束有效且法向力至少 0.05 N，再按 geom/body ID 识别 Cube、左右手指、桌面和地面。

0.05 N 只是过滤微弱接触的阈值，不是能托住 0.981 N 重量的夹持力保证。`data.ncon>0` 更不能直接代表抓住 Cube。

把左右接触法向统一为“作用于 Cube 的方向”，令 c 为 Cube 中心、y 为 Hand 世界闭合轴，候选夹持要求：

\[
(p_L-c)\cdot y>0.005,\qquad
(p_R-c)\cdot y<-0.005;
\]

\[
n_L\cdot y<-0.5,\qquad
n_R\cdot y>0.5,\qquad
n_L\cdot n_R<-0.5.
\]

即两侧有力、接触点分居两侧、法向相向。这个判断仍是瞬时候选证据，后续必须结合持续时间、离桌高度与物体速度。

| 证据 | 能说明什么 |
| --- | --- |
| close command | 发送了闭合意图 |
| finger_contact | 至少一个手指有有效 Cube 接触 |
| grasp_candidate | 双侧接触几何/法向合理 |
| stable grasp | 候选夹持和低速条件持续成立 |
| stable lift | 持续夹持、真实离桌、低速且稳定保持 |
| final place | 已抬升过，目标处受桌面支撑，手指分离、撤离后仍合格 |

## 6. Cube 最低点与稳定计时

旋转方块的最低点不能总写成“中心 Z−0.025”。令半边长向量 h、旋转矩阵 R，则：

\[
z_{\min}=z_c-\sum_{j=1}^{3}|R_{zj}|h_j,
\qquad clearance=z_{\min}-z_{\text{table}}.
\]

这能正确处理方块倾斜，避免某角仍压在桌面上时仅凭中心升高误判抬升。

连续稳定计时：

\[
T_{k+1}=
\begin{cases}T_k+\Delta t,&条件为真\\0,&否则.\end{cases}
\]

Day12 按真实 data.time 计时，同一时刻重复调用不能增加稳定时间；学习环境按物理子步更新。一次接触或一帧位置合格都不足以判完整成功。

## 7. 抓取方向和 TCP—物体偏移

规则抓取令工具 +Z 朝世界 -Z，以 Cube 水平轴确定闭合方向 y，再用 x=y×z 构造右手工具目标方向。

夹住后 Cube 中心一般不与 TCP 重合。先记录局部偏移：

\[
d^T=R_T^T(p_C-p_T).
\]

若要把 Cube 中心放到 `p_C^*`，工具方向为 `R_T^*`：

\[
p_T^*=p_C^*-R_T^*d^T.
\]

持物过程中微滑会改变偏移，因此在抬升、运输、放置阶段重新估计，同时仍检查滑脱。Day15 专家工具方向固定，以世界系 Cube−TCP 偏移实现相应补偿；不能将其等同于任意姿态变化下的完整位姿操作。

## 8. Day12 规则状态机

| 阶段 | 控制动作 | 转移证据 |
| --- | --- | --- |
| IDLE | 保持合法关节命令并张开夹爪 | Cube 在桌面且静止，臂/夹爪准备好 |
| PRE_GRASP | 朝下移动到物体上方约 0.12 m | 真实 TCP 位置/姿态/速度及开度稳定合格 |
| APPROACH | 缓慢下降到抓取位姿 | 真实到达并停稳 |
| CLOSE_GRIPPER | 闭合并保持手臂 | 双侧合理夹持持续 0.25 s |
| VERIFY_GRASP | 保持夹持，不急于抬起 | 候选夹持与 Cube 静止继续成立 |
| LIFT | 记录夹持偏移，抬升约 0.12 m | 到达、夹持、无桌/地支撑、clearance≥0.04 m、低速，持续 0.5 s |
| TRANSPORT | 按物体目标反算 TCP 并搬运 | 目标 XY 接近、仍离桌且被稳定夹持 |
| PLACE | 重测偏移，缓慢下放 | Cube 在目标处、静止且真正受桌面支撑 |
| RELEASE | 张开夹爪 | 实际开度、手指分离、落点和支撑稳定合格 |
| RETREAT | 工具上撤约 0.12 m | TCP 离开 Cube，放置条件继续成立 |
| SUCCESS/FAILURE | 终态 | 独立结果复核／明确失败原因 |

阶段规划先预检路点 IK，再执行平滑关节参考。它不是全臂碰撞规划，实际接触/失败监测仍不可缺少。

滑脱检查同时看候选夹持是否消失和 TCP—Cube 相对偏移是否超过 0.018 m；Day12 异常持续约 0.12 s 才报失败，避免瞬态接触波动。Day15 专家的相关宽限默认是 0.16 s，两套控制器的时间参数不能混用。

RELEASE 不等于 SUCCESS：撤离过程仍可能推走 Cube，最终 result 还会复查。阶段超时、抓手超时和总时长提供独立终止保障。

## 9. 环境的四种物理任务判定

以下为 Day13 基类及 Day15 继承的任务阈值；不同于规则状态机自己的转移计时：

| 任务 | 必须满足的物理条件 |
| --- | --- |
| reach | TCP 位置误差 <9 mm，姿态误差 <0.035 rad，臂最大速度 <0.10 rad/s，持续 0.4 s |
| grasp | 合理双侧接触，Cube 线速度 <0.02 m/s、角速度 <0.20 rad/s，臂低速，持续 0.5 s |
| lift | grasp 条件 + 无桌/地支撑 + 最低点离桌至少 4 cm，持续 0.5 s |
| pick_place | 曾真实稳定 lift，最终落点/支撑/速度/松爪/撤离条件全部持续 0.5 s |

最终抓放的具体条件为：

- XY 误差 <0.012 m，Z 误差 <0.004 m，最低点与桌面差绝对值 <0.004 m。
- Cube 有真实桌面支撑，无地面支撑、无手指有效接触。
- 实际名义开度至少 0.07 m；TCP 与 Cube 距离至少 0.08 m。
- Cube 线/角速度合格，而且 has_lifted 已由真实稳定抬升置位。

has_lifted 防止“物体初始就在目标处，直接张开夹爪就算抓放成功”。物体被弹起但没有稳定夹持，也不能仅靠瞬时高度置位。

## 10. 奖励、故障与真实证据

Day13 的 approach、grasp、height、placement、release 等密集项使用折扣势差，配合距离、动作、动作变化、IK/碰撞成本及一次性成功/失败奖励。抓放任务不能靠反复开合、等待在某个接触状态刷固定正奖励。

高度势在合理夹持等条件下才有效；没有夹住的弹起不等于 lift。IK 无效或物理失败时禁止正奖励。奖励分项之和应等于 step 返回的 reward，但高奖励本身不等于真实成功。

| 失败类别 | 证据/处理 |
| --- | --- |
| 掉落 | 地面接触或物体无支撑且最低点明显低于桌面 |
| 手指撞桌 | 有效手指—桌面接触，按环境配置终止 |
| IK 失败 | 保持上一合法目标；连续失败到上限后终止 |
| 物理数值异常 | 非有限状态或 warning，返回明确数值失败，不伪造成功 |
| 专家阶段失败 | 超时/持续滑脱，记录 abort，不改写环境终止事实 |

历史故障注入区分了“状态监测器能否拒绝假证据”与“真实动力学下能否完成任务”。原自动回归入口现已删除，不能把其历史通过记录描述成仍可直接重跑的测试套件。
